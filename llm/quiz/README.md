# Quiz — 교과 암기 퀴즈를 만드는 스킬

[`Jiri`](https://github.com/pwh831/Jiri)(지역이해 암기 퀴즈)와
[`Japan`](https://github.com/pwh831/Japan)(일본어 단어시험)을 두 번 만들면서
같은 것을 두 번 지었습니다. 세 번째부터는 **데이터만 채우면 되도록** 그 틀을 스킬로 뽑았습니다.

## 무엇이 들어 있나

```
.claude/skills/quiz/      교과 암기 퀴즈를 만드는 스킬
  SKILL.md                  만드는 순서와 원칙
  references/               데이터 계약 · 문제 유형 · 채점 규칙 · 점검 목록
  assets/                   과목에 상관없는 엔진 · 빌드 · 검사 도구
subjects/문학과영상/       이 스킬로 만든 첫 과목 (152항목)
```

## 스킬

Claude Code 에서 이 저장소를 열면 `quiz` 스킬이 잡힙니다.
"○○ 퀴즈 만들어줘" 라고 하면 이 순서로 돕니다.

1. **학습지·교과서와 시험 범위를 받는다** — 자료 없이 데이터부터 쓰지 않는다
2. `subjects/<과목>/` 에 엔진을 복사한다 (엔진은 고치지 않는다)
3. `SUBJECT`·`AREAS`·`UNITS`·`CATS` 로 **구조를 먼저** 짠다 — 학습지 단원을 그대로
4. `ITEMS` 에 항목과 서술을 채운다
5. `node verify.js` → `python3 build.py` → `node smoke.js`
6. 산출물을 눈으로 열어 본다
7. README 와 PRD 를 쓴다 — **자료 없이 채운 부분이 있으면 반드시 밝힌다**

## 이 틀의 요점

**엔진은 과목마다 고치지 않습니다.** `index.html` 은 `data/items.js` 만 읽고,
문제문에 쓸 낱말("이 **쇼트**의 **뜻**을 떠올려 보세요")까지 데이터가 정합니다.
엔진을 고쳐야 할 것 같으면 거의 언제나 데이터 설계가 잘못된 것입니다.

**다섯 유형을 데이터에 적지 않습니다.** 이름·설명·헷갈리는 짝만 적으면 엔진이
이름 쓰기 · 설명 고르기 · 설명 → 이름 · O·X 판별 · 떠올리기를 만들어 냅니다.
한 번 잘 적은 데이터가 다섯 방향으로 외워집니다.

**오답 보기를 지어내지 않습니다.** 전부 다른 항목의 진짜 설명이고, **헷갈리는 짝에서
먼저** 길어옵니다. 아무 항목이나 섞으면 보기만 보고도 답이 보여서, 정작 시험에서 가르지
못하는 것을 연습하지 못합니다.

**파일 하나로 돌아야 합니다.** 태블릿에서는 폴더째 옮기는 길이 막혀 있습니다.
`build.py` 산출물이 진짜 배포본이고, 그것이 열리는지 확인해야 끝입니다.

## Jiri · Japan 과의 관계

두 저장소는 그대로 둡니다. 지도 좌표 도구(`Jiri/tools/`)나 가나 채점·활용 규칙
(`Japan/index.html`)처럼 그 과목에만 있는 것이 많아, 억지로 이 엔진에 맞추면 둘 다 나빠집니다.
이 스킬은 **세 번째부터**를 위한 것입니다.

다만 두 저장소에서 배운 것은 전부 `references/` 에 옮겨 적었습니다.
빌드 산출물의 문법 검사(Jiri 에서 데이터 오타가 빈 화면이 된 뒤에 생김),
서답형을 핵심으로 두는 것과 숙달 판정을 그 유형만 세는 것(Japan),
헷갈리는 짝을 나란히 놓는 대비 출제(Japan 의 `どこか`/`どこが`) 같은 것들입니다.

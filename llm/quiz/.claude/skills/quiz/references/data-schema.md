# 데이터 계약

`data/items.js` 는 여섯 개를 내보낸다. 엔진은 이것만 읽고, 이것 말고는 아무것도 모른다.

```js
module.exports = { SUBJECT, AREAS, UNITS, CATS, MEDIA, ITEMS };
```

마지막 줄의 `if (typeof module !== "undefined")` 는 `verify.js`(node) 를 위한 것이다.
`build.py` 가 산출물에서 그 줄을 지우므로 브라우저에서는 문제가 없다. **지우면 안 된다.**

---

## SUBJECT

| 필드 | 필수 | 뜻 |
|---|---|---|
| `key` | ✔ | `localStorage` 키 접두어. **과목마다 달라야** 학습 기록이 안 섞인다 |
| `title` | ✔ | 화면 제목 · 문서 제목 |
| `file` | ✔ | `build.py` 산출물 파일 이름 |
| `lead` | | 제목 밑 한 줄 설명 |
| `eyebrow` | | 머리말 왼쪽 작은 글씨. 뒤에 `· N ITEMS` 가 자동으로 붙는다 |
| `icon` | | 파비콘에 쓸 이모지 한 글자 |
| `web` | | Artifact 발행용본 파일 이름. 없으면 안 만든다 |
| `kind` | | 문제문의 기본 명사 — "이 **항목**의 이름은?". 갈래별로 덮어쓴다 |
| `what` | | 서술을 부르는 기본 말 — "…의 **설명**을 떠올려 보세요" |
| `writeHint` | | 서답형 입력칸 밑 안내 |
| `suffixes` | | 있으나 없으나 같은 말로 치는 꼬리말 배열 (`grading.md`) |
| `equiv` | | 표기만 다른 같은 말 묶음 배열 (`grading.md`) |
| `notesLabel` / `notesHint` | | `notes` 를 켜는 홈 화면 버튼의 문구 |

`notes` 가 하나도 없으면 그 버튼은 아예 안 나온다.

## AREAS

```js
{ id:"visual", title:"영상 언어" }
```

홈 화면에서 한 덩어리로 켜고 끄는 큰 틀. 둘~셋이 적당하다. 하나여도 된다.

**`AREAS` 는 오답 보기를 길어오는 3순위이기도 하다.** 같은 영역 안의 항목이 서로
그럴듯한 오답이 되도록 묶는다.

## UNITS

```js
{ id:"u003", no:"003", title:"편집과 몽타주", area:"visual", cats:["cut","montage"], exam:false }
```

| 필드 | 필수 | 뜻 |
|---|---|---|
| `id` | ✔ | 내부 식별자 |
| `no` | ✔ | 화면에 보이는 단원 번호. **학습지 번호를 그대로** 쓴다 |
| `title` | ✔ | 단원 이름 |
| `area` | ✔ | `AREAS[].id` |
| `cats` | ✔ | 이 단원에 속한 갈래 키. **여기 없는 갈래는 홈 화면에 안 나온다** |
| `exam` | | `false` 면 시험 범위 밖 — 자료는 남되 처음엔 선택되지 않고 `범위 밖` 이라고 뜬다 |

## CATS

```js
{ key:"shot", label:"쇼트의 크기", unit:"u001", kind:"쇼트", what:"뜻" }
```

| 필드 | 필수 | 뜻 |
|---|---|---|
| `key` | ✔ | `ITEMS[].category` 가 가리키는 값 |
| `label` | ✔ | 홈 화면 칩에 뜨는 이름 |
| `unit` | ✔ | `UNITS[].id`. 그 단원의 `cats` 에도 이 키가 있어야 한다 |
| `kind` | | 이 갈래의 문제문 명사. "다음 설명에 해당하는 **쇼트**는?" |
| `what` | | 이 갈래의 서술을 부르는 말. "…의 **뜻**을 떠올려 보세요" |

한 갈래는 **한 세션에 풀 만한 크기**(10~30항목)로 자른다. 갈래가 곧 사용자가 고르는 단위다.

## MEDIA

그림을 단서로 쓰는 과목에서만. 안 쓰면 `const MEDIA = {};`

```js
const MEDIA = {
  kr_admin: { title:"우리나라 행정구역", image:"assets/maps/kr_admin.png", labeled:false },
  honam:    { title:"호남 지방",        image:"assets/maps/honam.png",    labeled:true  }
};
```

- `labeled:true` — 그림에 번호(①②③)가 인쇄되어 있다. 항목은 `num` 을 갖는다
- `labeled:false` — 백지 그림. 항목은 `marker:{x,y}` (그림 크기에 대한 **백분율**) 를 갖는다

`build.py` 가 이 경로의 파일을 base64 로 산출물 안에 심는다. 경로는 과목 폴더 기준 상대 경로다.

## ITEMS

```js
{ id:"v07", category:"shot", name:"클로즈업", aliases:["클로즈 업","C.U."],
  features:["인물의 얼굴이나 사물의 한 부분을 화면에 가득 채워 보여 준다",
            "표정의 미세한 변화나 감정의 고조를 강조할 때 쓴다"],
  notes:[], confuse:["v08"],
  media:"honam", num:7 }
```

| 필드 | 필수 | 뜻 |
|---|---|---|
| `id` | ✔ | **전 항목에서 유일**. 학습 기록의 열쇠이므로 **한번 정하면 안 바꾼다** (바꾸면 그 항목의 진도가 날아간다) |
| `category` | ✔ | `CATS[].key` |
| `name` | ✔ | 정답이 되는 이름 |
| `aliases` | | 정답으로 쳐 줄 다른 표기 |
| `features` | ✔※ | 학습 자료 본문의 서술 = 출제 대상. 항목당 2~4개 |
| `notes` | | 각주·심화. **기본 출제 제외**, 홈에서 켤 때만 나온다 |
| `confuse` | | 시험에서 가르기 어려운 항목의 `id`. 오답 보기를 여기서 **먼저** 길어온다 |
| `media` | | `MEDIA` 의 키 |
| `num` | | `labeled:true` 그림에서 이 항목의 번호 |
| `marker` | | `labeled:false` 그림에서 위치 `{x,y}` (백분율) |

※ `features` 와 `media` 중 **적어도 하나**는 있어야 한다. 둘 다 없으면 낼 문제가 없어
출제에서 빠진다.

### id 규칙

갈래를 짐작할 수 있는 접두어 + 두 자리 숫자를 권한다 (`sh01`, `mv03`, `ed12`).
**절대 재사용하지 않는다.** 항목을 지워도 그 id 는 비워 둔다 — 새 항목에 물려주면
남의 진도가 붙는다.

### 서술(features) 쓰는 법

- **이름을 서술 안에 쓰지 않는다.** 답이 그대로 새어 나간다 (`verify.js` 가 WARN 으로 잡는다)
- **한 문장, 한 가지.** 두 가지를 한 문장에 담으면 O·X 에서 반만 맞는 문장이 된다
- **그 항목에만 해당하게.** 여러 항목에 해당하는 문장은 '설명 → 이름'의 답을 둘로 만든다
- **학습 자료의 말을 쓴다.** 시험은 자료의 표현으로 나온다. 매끄럽게 고쳐 쓰지 않는다

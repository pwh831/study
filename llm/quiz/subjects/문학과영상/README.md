# 문학과 영상 암기 퀴즈

「문학과 영상」의 용어와 개념을 다섯 방향으로 반복해서 외우는 프로그램.
[`Jiri`](https://github.com/pwh831/Jiri)(지역이해)·[`Japan`](https://github.com/pwh831/Japan)(일본어 단어시험)과
같은 틀이고, 그 틀을 뽑아낸 [`quiz` 스킬](../../.claude/skills/quiz/SKILL.md)로 만들었습니다.

## 실행

### 파일 하나로 (PC)

**`문학과영상-퀴즈.html`** 이 파일 하나만 받아서 더블클릭하면 됩니다.
폴더 구조도, 인터넷도 필요 없습니다(글꼴만 있으면 더 예쁘게 보일 뿐).

태블릿·휴대폰은 내려받은 HTML 을 브라우저로 여는 길이 막혀 있어 파일 방식이 통하지 않습니다.
그때는 `munhak-yeongsang-web.html` 을 Artifact 로 발행해 링크로 엽니다.

### 저장소를 통째로 받았다면

`index.html` 을 여세요. 단, `data/` 폴더가 **같은 자리에 함께 있어야** 합니다.

## ⚠️ 범위와 출처 — 먼저 읽어 주세요

**이 데이터는 학습지나 교과서를 보고 옮긴 것이 아닙니다.**
2022 개정 교육과정 「문학과 영상」에서 공통으로 다루는 **표준 용어와 정의**로 채웠습니다.

- 개념과 정의 자체는 교과서가 대체로 같습니다. 그래서 지금 이대로도 공부가 됩니다.
- 그러나 **단원 구분·서술의 표현·시험 범위는 학교와 교과서마다 다릅니다.**
- 시험은 학습지의 표현으로 나옵니다. **학습지를 주시면 그 문장으로 갈아 끼우겠습니다.**

학습지를 반영할 때 하는 일:

1. `data/items.js` 의 `features` 를 학습지 문장으로 교체
2. `UNITS` 를 학습지 단원 구조에 맞추고, 번호(`no`)를 학습지 번호로
3. 범위 밖 단원에 `exam:false` — 자료는 남고 처음에는 선택되지 않습니다
4. 이 절을 고쳐 무엇을 어디서 가져왔는지 다시 적습니다

## 문제 유형

같은 데이터에서 엔진이 다섯 가지를 만들어 냅니다. 홈에서 하나만 골라 풀 수도 있습니다.

| 유형 | 형태 | 예 |
|---|---|---|
| 이름 쓰기 | 설명 보고 이름 **타이핑** | "얼굴이나 사물의 한 부분을 화면에 가득 채워…" → `클로즈업` |
| 설명 고르기 | 이름 → 옳은 설명 5지선다 | "평가에 대한 설명으로 옳은 것은?" |
| 설명 → 이름 | 설명 → 이름 5지선다 | "카메라를 기울여 수평선이 비스듬하게 찍힌다" → 더치 앵글 |
| O·X 판별 | 붙여 준 서술이 그 용어의 것인지 판단 | "교차 편집 — 시간이 다른 두 이야기를 나란히" → X (평행 편집) |
| 떠올리기 | 보지 않고 떠올린 뒤 확인 | "롱 테이크의 설명을 떠올려 보세요" → 3가지 확인 |

**가운데가 아니라 첫 번째가 핵심입니다.** 고르는 것만으로는 시험에서 못 씁니다.

**오답 보기는 지어내지 않습니다.** 전부 다른 항목의 진짜 설명이고, **헷갈리는 짝에서 먼저**
길어옵니다 — 팬과 틸트, 하이 앵글과 버즈 아이 뷰, 반영론과 표현론처럼 시험에서 가르기
어려운 것을 보기에 함께 올립니다. 채점 뒤에는 각 오답 밑에 **그 문장의 진짜 주인**을 적어
주므로, 한 문제에서 다섯 항목을 봅니다.

## 채점

- 괄호·띄어쓰기·가운뎃점은 무시합니다 — `클로즈업` = `클로즈 업` = `C.U.`
- `쇼트`·`숏`·`샷` 은 같은 말로 칩니다. `미장센`/`미쟝센`, `몽타주`/`몽타쥬` 도 마찬가지
- 꼬리말 `기법`·`효과` 는 있으나 없으나 정답 — `쿨레쇼프 효과` = `쿨레쇼프`
- 오타 한 글자는 "정답 · 오타" 로 봐주되, **서로 한 글자 차이인 이름은 봐주지 않습니다** —
  `페이드인`/`페이드아웃`, `F.I.`/`F.O.` 에서 오타를 봐주면 한쪽을 쓰고 다른 쪽 정답을 받습니다

## 기능

- 단원 단위 또는 세부 갈래 단위로 범위 선택
- 오답 우선 출제, 오답 노트 다시 풀기, 연속 3회 정답 시 숙달 처리
- 학습 기록은 브라우저에 저장(localStorage)

## 구성

```
index.html      앱 전체 (UI + 퀴즈 엔진) — 과목마다 고치지 않는다
data/items.js   문제 데이터 152항목 · 서술 310개  ← 고치는 곳은 여기뿐
build.py        데이터를 인라인해 단일 HTML 생성
verify.js       데이터 계약 검사
smoke.js        실제 브라우저로 한 세션을 끝까지 풀어 보는 종단 시험
문학과영상-퀴즈.html        배포용 단일 파일 (build.py 산출물)
munhak-yeongsang-web.html  Artifact 발행용본
docs/PRD.md     요구사항 정의서
```

## 고친 뒤

```bash
node verify.js      # 데이터 계약 — ERROR 가 있으면 고친다
python3 build.py    # → 문학과영상-퀴즈.html (문법 검사 포함)
node smoke.js       # 진짜 브라우저로 한 세션 (playwright 필요, 없으면 건너뜀)
```

**빌드를 안 돌리면 산출물은 옛것 그대로입니다.**

## 항목 추가

`data/items.js` 의 `ITEMS` 배열에 객체를 하나 넣으면 됩니다.

```js
{ id:"sh11", category:"shot", name:"미디엄 롱 쇼트", aliases:["니 쇼트","M.L.S."],
  features:["무릎 위쪽까지를 담는 크기다",
            "인물의 몸짓과 표정을 한꺼번에 볼 수 있는 절충점이다"],
  confuse:["sh03","sh04"] }
```

- `id` 는 **한번 정하면 안 바꿉니다** — 학습 기록의 열쇠라서, 바꾸면 그 항목의 진도가 날아갑니다
- 서술 안에 **그 항목의 이름을 쓰지 않습니다** — 답이 그대로 새어 나갑니다
- 헷갈리는 짝은 **서로** `confuse` 로 걸어 둡니다

새 갈래는 `CATS` 에 한 줄을 넣고 그 단원의 `cats` 에도 키를 더합니다.
자세한 계약은 [`data-schema.md`](../../.claude/skills/quiz/references/data-schema.md).

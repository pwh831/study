## 1. 개요

### 1.1 배경

「문학과 영상」은 외울 용어가 많다. 쇼트의 크기만 열 가지이고, 앵글·카메라 움직임·편집·
시점·각색 전략·비평 관점이 각각 한 묶음씩 있다. 문제는 **하나하나가 어렵지 않고 서로
헷갈린다**는 것이다. 롱 쇼트와 풀 쇼트, 팬과 틸트, 교차 편집과 평행 편집, 반영론과 표현론 —
따로 보면 다 알 것 같고 시험지에서 나란히 놓이면 갈리지 않는다.

종이 정리본은 답이 옆에 보여서 "아는 것 같은 느낌"만 남는다. **직접 쓰고 틀리는 것을
확인하는** 것이 이 프로그램의 존재 이유다.

같은 사용자가 쓰는 `Jiri`(지역이해)·`Japan`(일본어 단어시험)과 **같은 구조** —
빌드 도구 없는 단일 HTML + 데이터 파일 + localStorage — 를 따른다. 두 번 검증된 틀이므로
새로 설계하지 않았고, 이번에는 그 틀을 `quiz` 스킬로 뽑아내 세 번째부터는 데이터만 채우면
되게 했다.

### 1.2 목표

- 헷갈리는 짝을 **한 문제 안에서 함께 보여** 가르는 연습을 시킨다.
- 고르는 것으로 끝내지 않고 **직접 타이핑**해서 쓸 수 있는지 확인한다.
- 틀린 항목을 추적해 맞을 때까지 반복 노출시킨다.
- 단원·갈래를 골라 오늘은 이것만 풀 수 있게 한다.
- 파일 하나로 어디서나 열린다.

### 1.3 비목표

- **작품 감상 문제** — "이 장면에서 감독의 의도는?" 류는 정답이 하나가 아니다.
  이 엔진은 용어와 개념을 묻는 도구다.
- **서술형 답안 채점** — 핵심어 타이핑까지가 한계다.
- **영상 재생** — 화면을 붙이면 파일 하나로 안 돈다. 필요하면 정지 화면을 `MEDIA` 로 넣는다.
- 다중 사용자 계정 / 서버 / 클라우드 동기화
- AI 자동 문제 생성 — 데이터는 자료 기반 수기 입력

### 1.4 성공 기준

- 헷갈리는 짝이 5지선다 보기에 함께 올라온다.
- 한 세션(20문항)을 5분 안에 푼다.
- 오답이 정답 처리될 때까지 반복 출제된다.
- 새로고침·재접속 뒤에도 진도가 남는다.
- 휴대폰 너비에서 가로 스크롤이 생기지 않는다.

## 2. 사용자

| 구분 | 설명 |
|---|---|
| 주 사용자 | 「문학과 영상」 수강생 본인 (단일 사용자) |
| 사용 환경 | 태블릿·휴대폰 우선, PC 브라우저도 지원 |
| 사용 시점 | 시험 2~3주 전부터 매일 10~20분 |

**핵심 사용자 스토리**

1. 오늘은 영상 언어만, 내일은 각색만 — 갈래를 골라 풀고 싶다.
2. 설명을 보고 용어를 **직접 써 보고** 맞았는지 확인하고 싶다.
3. 팬과 틸트가 매번 헷갈린다. 둘을 나란히 놓고 가르는 연습을 하고 싶다.
4. 시나리오 약어(F.I.·O.L.·NAR.)를 외우고 싶다.
5. 틀린 것만 모아서 다시 풀고 싶다.
6. 시험 전날 전체를 한 번 훑고 싶다.

## 3. 데이터

### 3.1 범위

152항목 · 서술 310개 · 8단원 · 20갈래. 구성은 [README](../README.md) 참고.

### 3.2 출처 — 알려진 한계

**현재 데이터는 2022 개정 교육과정 「문학과 영상」의 표준 용어로 채운 것이고,
사용자의 학습지나 교과서를 보고 옮긴 것이 아니다.**

개념과 정의는 교과서가 대체로 같으므로 지금 이대로도 공부가 된다. 그러나
단원 구분·서술의 표현·시험 범위는 학교마다 다르고, **시험은 학습지의 표현으로 나온다.**

학습지를 받으면 `features` 를 그 문장으로 갈아 끼우고, `UNITS` 를 학습지 단원 구조에
맞추고, 범위 밖 단원에 `exam:false` 를 달고, README 의 '범위와 출처'를 고친다.
**앱 코드는 건드릴 것이 없다.**

### 3.3 서술의 규칙

- 서술 안에 그 항목의 이름을 쓰지 않는다 (답이 새어 나간다)
- 한 문장에 한 가지 (O·X 에서 반만 맞는 문장이 되면 안 된다)
- 그 항목에만 해당하게 (설명 → 이름의 답이 둘이 되면 안 된다)
- 항목당 2~4개 (하나면 매번 같은 문제, 다섯이 넘으면 떠올리기가 불가능)

## 4. 기능

### 4.1 다섯 유형

유형은 데이터에 적지 않는다. 같은 항목에서 엔진이 다섯 가지를 만든다.
자세한 것은 [`question-types.md`](../../../.claude/skills/quiz/references/question-types.md).

### 4.2 헷갈리는 짝 (`confuse`)

이 과목의 핵심 설계. 오답 보기를 **`confuse` → 같은 갈래 → 같은 영역 → 전체** 순으로
길어온다. 걸어 둔 짝의 예:

| 짝 | 왜 헷갈리나 |
|---|---|
| 롱 쇼트 / 풀 쇼트 / 미디엄 쇼트 / 바스트 쇼트 | 크기의 정도만 다르다 |
| 팬 / 틸트 | 방향만 다르다 |
| 달리 / 줌 | 결과가 비슷해 보이고 공간감에서 갈린다 |
| 하이 앵글 / 버즈 아이 뷰 | 정도의 차이다 |
| 교차 편집 / 평행 편집 | 이름도 뜻도 가깝다 |
| 페이드인 / 페이드아웃, F.I. / F.O. | 한 글자 차이다 |
| 반영론 / 표현론 / 효용론 | 이름의 꼴이 같다 |
| 패러디 / 오마주 / 표절 | 경계가 판단의 문제다 |
| 신 / 시퀀스 / 쇼트 | 상위어–하위어 관계다 |

### 4.3 진도

항목별 `{right, wrong, streak, last}` 를 localStorage 에 저장. 연속 3회 정답이면 숙달.
'오답 우선' 은 틀린 횟수·연속 정답·처음 보는지를 가중치로 삼아 뽑는다.

### 4.4 채점

[`grading.md`](../../../.claude/skills/quiz/references/grading.md) 참고.
이 과목에 건 규칙: 꼬리말 `기법`·`효과`, 같은 말 `쇼트`/`숏`/`샷`·`미장센`/`미쟝센`·
`몽타주`/`몽타쥬`·`시퀀스`/`시퀜스`.

**한 글자 차이인 이름은 오타를 봐주지 않는다.** 엔진이 시작할 때 항목 이름을 전부 대조해
그런 이름을 자동으로 찾아낸다. `페이드인`/`페이드아웃`, `F.I.`/`F.O.` 가 여기 걸린다.

## 5. 기술

| 항목 | 결정 | 이유 |
|---|---|---|
| 빌드 도구 | 없음 | 파일 하나로 돌아야 한다. 태블릿에는 폴더가 없다 |
| 엔진 | `index.html` 고정 | 과목마다 고치면 고친 것이 한쪽에만 남는다 |
| 저장 | localStorage | 서버 없이 진도가 남는 유일한 길 |
| 그림 | 쓰지 않음 | 이 과목은 텍스트만으로 성립한다. 필요하면 `MEDIA` 로 넣는다 |
| 검사 | `verify.js` + `build.py` 문법 검사 + `smoke.js` | 데이터 · 코드 · 실제 화면을 각각 다른 것이 본다 |
